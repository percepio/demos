# Run on STM32U585 hardware

This optional target supports the **ST B-U585I-IOT02A / STM32U585** board.
Complete the [host setup](../README.md) with Zephyr, its Python environment and
the Zephyr SDK. QEMU is only needed for the emulated target.

## Install and configure OpenOCD

Use ST's OpenOCD distribution, for example the one bundled with STM32CubeIDE.
It must supply `interface/stlink-dap.cfg` and `target/stm32u5x.cfg`.
In [.vscode/settings.json](../.vscode/settings.json), set:

```json
{
  "demo.openOcdPath": "/absolute/path/to/openocd",
  "demo.openOcdScripts": "/absolute/path/to/st_scripts"
}
```

On Windows, use `openocd.exe` and forward slashes in JSON paths. On Linux,
install the probe vendor's udev rules and give your user USB access.
The SDK's Arm GDB is used, just as for QEMU.

## Build and debug

Use a **TrustZone-disabled, single-image** board configuration.
The supplied launch configuration is for `b_u585i_iot02a`, without `/ns` or TF-M.

1. Connect the board's ST-LINK USB port.
2. Select **STM32U585: ST-LINK (OpenOCD)** in Run and Debug.
3. Press **F5** to build incrementally, program the board and stop at `main`.
4. Press **F5** to continue or **Shift+F5** to release the debug server/probe.

For a pristine build, press **Ctrl+Shift+B** and choose **STM32U585: clean build**.
With the default settings, images are under `build/b_u585i_iot02a/local-debug/zephyr`.
The build does not require a connected board or OpenOCD.

From a terminal with the [Zephyr environment](setup-reference.md#terminal-environment):

```text
python -m west build -b b_u585i_iot02a -p always -d build/b_u585i_iot02a/local-debug . -- -DDEMO_PERCEPIO_SOURCE=local
python -m west flash -d build/b_u585i_iot02a/local-debug
```

Zephyr selects its board runner for `west flash`/`west debug`. Use their `--context`
options to inspect available runners and tool overrides. The default `west flash`
runner requires STM32CubeProgrammer. To use ST OpenOCD instead, select
`--runner openocd` and configure its executable/script paths with that runner's
options (`west flash -d build/b_u585i_iot02a/local-debug --runner openocd --context`).
The VS Code F5 configuration
instead owns OpenOCD directly and uses the small board script in
[boards/support](../boards/support/b_u585i_iot02a.cfg), adapted from Zephyr's board
configuration to respect the debugger-assigned GDB port.

## Output and Detect

Open the ST-LINK virtual COM port at **460800 baud** to see USART1 output.
Capture that serial output to a log file. Follow the [Detect steps](../README.md#5-view-alerts-in-percepio-detect)
using `build/b_u585i_iot02a/local-debug/zephyr/zephyr.elf` and that serial log.
Hardware sessions do not write `qemu_last_session.log`.

If ST-LINK cannot be opened, close other tools using the probe, check USB drivers
and permissions, and reconnect the board. `spawn openocd ENOENT` means the
executable path needs correcting. Runtime/flashing validation of this new VS Code
hardware configuration is recorded separately from successful compilation in the
[development guide](development-setup.md).
